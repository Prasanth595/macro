query is only the content or topic to match, after removing the search instruction, all requested content-category wording, and entire supported sender/channel filter clauses. Exclude topic-introducing words such as "about" or "containing". Never repeat text used by search_scope, search_from or search_in as search keywords. A category can be described more than once: "channels for messages" specifies message content, not a topic. Return null when only category and filter instructions remain.
Examples: "search channels for messages from user@example.com" has query null; "search channels for messages from user@example.com in #team" has query null; "search channels for messages from user@example.com about budget" has query "budget". Do not leave "messages from user@example.com" or "messages" in the query after using that wording for filters.
The same applies to a person's name instead of an address: "search channels for messages from Person A" has search_from ["Person A"] and query null. The sender's name is entirely a filter, never a keyword, unless the author separately requests that literal name as the content to match.
Preserve actual keyword phrases, quoted literal topics, dates and ordinary uses of "in" or "from" within the topic. For example, "search messages from user@example.com about growth in 2026" has query "growth in 2026". Unsupported filters remain keyword text: "search documents from user@example.com" has query "from user@example.com", because document sender filters are unsupported.
